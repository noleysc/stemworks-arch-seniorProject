Where the product is going

The complete project

By the end of next semester, Stemworks should be a hosted web platform owners can use every day—not just a classroom prototype.

One board for the founder

See money in motion, what needs attention, and how each venture is doing—without mixing businesses together.

Working desks for each venture

Rentals collection, product operations for Jade Flowers, and ticketed experiences for Pampered Soul—all feeding the same system.

Ready for real use

Hosted online, connected to a shared database, with a clear handoff path for Diaz Ventures to maintain after the course.

Long-term shape

Ventures plug into Stemworks through separate modules. Outside tools (payments, booking channels, inventory systems) connect when needed. Stemworks does not replace a hotel reservation system.

How we run the project

Project management plan

Meeting schedule

  • Weekly team sync to set the next slice
  • Short mid-week check-in on blockers
  • Sponsor updates when a desk is ready to show
  • Pre-demo dry run before presentation day

Timeline

  • Iterative slices, not one big release
  • Earlier sprints: desks and dashboard
  • Current sprint: demo, docs, hardening
  • Next: hosted delivery and handoff

Handling issues

  • Clear owners: lead, backend, dashboard, frontend
  • Peer review before work lands on main
  • Automated checks before a slice is accepted
  • Escalate stack or scope changes to the sponsor

Risks we already plan for

Outside service changes, keeping businesses’ data separate, and demo reliability on presentation day. We keep a backup recording, freeze features before the talk, and treat architecture rules as the guardrail when something unexpected appears.
